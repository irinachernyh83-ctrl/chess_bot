# Бесплатный хостинг для бота (Россия)

Боту нужен постоянный исходящий интернет и **живой процесс 24/7**: он работает
через MTProto (Telethon), а не через webhook. Поэтому «обычный бесплатный
хостинг сайтов» и serverless-платформы (Vercel, Netlify, Cloudflare Workers,
TeleBotHost) не подходят — там процесс запускается только на входящий запрос.

Ниже — что реально бесплатно в 2026 году и что из этого тянет бота.

## Сравнение

| Вариант | Что дают | Карта | 24/7 | Главные минусы |
| --- | --- | --- | --- | --- |
| **Свой телефон/ПК** ([termux.md](termux.md)) | сколько есть | нет | да | свет, железо, батарея; телефон должен быть в сети |
| **Render Free** | 512 МБ RAM, 750 ч/мес | нет | да, с «пингом» | засыпает через 15 мин без запросов; диск эфемерный |
| **Bot-Hosting.net Free** | 256 МБ RAM, 25 % CPU, 512 МБ диска | нет | да, без сна | продлевать вручную каждые 4 дня; диск эфемерный |
| **Bothost.ru Starter** | 256 МБ RAM, 0.25 vCPU, 0.5 ГБ SSD | нет | да | данные стираются при перезапуске; поддержка только сообщество |
| **Oracle Cloud Always Free** | до 4 ядер ARM, 24 ГБ RAM | нужна (иностранная) | да | сложная регистрация, часто отклоняют карты РФ |
| **Azure for Students** | $100 на 12 мес + бесплатные B1s | нет | да | нужен подтверждённый студенческий статус |
| **Beget / SmartApe / Timeweb / RUVDS / Amvera** | тест 3–30 дней | обычно нет | да, на время теста | потом 150–500 ₽/мес |
| **Yandex Cloud, VK Cloud** | грант на 60 дней | да | да | Yandex — только юрлицам; VK — нужен корпоративный домен |

Вывод: **бессрочно бесплатно** есть только два пути — своё железо
(телефон/старый ПК/малиновый Pi) или бесплатные тарифы бот-хостингов
с ручным продлением/эфемерным диском. Всё остальное — тестовые периоды.

**Выбор для этого бота — Render Free** (инструкция ниже): без карты, 512 МБ RAM,
готовый `render.yaml`, прямой доступ к Telegram. Запасной вариант —
Bot-Hosting.net, если Render не подойдёт по региону.

## Важно про `data/`

На всех бесплатных PaaS диск эфемерный: после перезапуска `data/chess.db` и
`data/chessbot.session` пропадают.

- сессия **восстанавливается сама** — бот логинится по токену, код ввода не нужен;
- обычные партии из SQLite **теряются** (незаконченные станут «битыми» в чатах);
- инлайн-партии и так живут только в памяти.

Если партии важны — либо платный тариф с volume, либо свой сервер/телефон.

## Render (выбранный вариант: бесплатно, без карты)

Почему он: не нужна карта, 512 МБ RAM (вдвое больше остальных бесплатных),
нормальный Docker-деплой, есть готовый `render.yaml`, сервис живёт в Франкфурте
и подключается к Telegram напрямую, без прокси.

1. Залей проект в GitHub. Без git это делается так: на github.com → **New
   repository** → имя `chess-bot` (можно Private) → **Create** → на странице
   репозитория **uploading an existing file** → перетащи распакованное
   содержимое `dist/chessbot-deploy.zip` (папки `chessbot`, `assets`, `deploy`,
   файлы `main.py`, `Dockerfile`, `render.yaml`, ...). `.env` и `data/` не нужны.
2. [dashboard.render.com](https://dashboard.render.com) → войти через GitHub →
   **New → Blueprint** → выбрать репозиторий → **Apply**.
   `render.yaml` уже задаёт Docker, план Free, регион Frankfurt и health-check `/`.
3. Render спросит `BOT_TOKEN` — вставь токен от @BotFather. `FINISHED_GAME_TTL`
   уже прописан (`600`). `MTPROXY`/`PROXY_URL` не добавляй: из Франкфурта
   Telegram доступен напрямую.
4. Дождись сборки (2–4 минуты). В логах должно быть
   `Бот запущен: @skldlgkjsjskfkkfheja_bot`, а статус сервиса — **Live**.
5. Поставь бесплатный пинг, иначе Render усыпит сервис через 15 минут без
   входящих запросов: [cron-job.org](https://cron-job.org) → Create cronjob →
   URL `https://<имя-сервиса>.onrender.com/` → каждые 5 минут → ожидать код 200.
   Подойдёт и UptimeRobot (монитор HTTP раз в 5 минут).

Что учитывать:

- бесплатный инстанс — 0.1 CPU, доска может рисоваться около секунды;
- 750 часов в месяц на всё рабочее пространство: один сервис 24/7 = 744 часа,
  второй бесплатный сервис уже не поместится;
- диск эфемерный: после редеплоя/рестарта `data/chess.db` пропадает (сессия
  бота восстановится сама), незаконченные обычные партии в чатах «сломаются»;
- если Render всё-таки потребует карту или не пустит по региону — переходи
  на Bot-Hosting ниже, там нет ни карты, ни GitHub.

## Bot-Hosting.net (запасной вариант: бесплатно, без карты, без сна)

1. Регистрация на [bot-hosting.net](https://bot-hosting.net) → **New deployment** →
   Python, загрузка архива или GitHub.
2. Start command: `python main.py`, переменные окружения — `BOT_TOKEN`,
   `FINISHED_GAME_TTL`.
3. Free: 256 МБ RAM, 25 % CPU, 512 МБ диска, постоянная работа, автоперезапуск.
4. Раз в 4 дня заходи в панель и жми **продлить** — иначе бот остановят.
5. Бэкапы раз в час с хранением 24 ч можно скачать из панели.

Если платформа ругается, что сервис не слушает порт, — задай переменную
`HEALTH_PORT=8080` (бот поднимет health-сервер).

## Bothost.ru (Россия, бесплатно, без карты)

1. Регистрация на [bothost.ru](https://bothost.ru) → создать бота → Telegram.
2. Загрузи код (GitHub или архив с `Dockerfile`), укажи `BOT_TOKEN`.
3. Free: 1 бот, 256 МБ RAM, 0.25 vCPU, 0.5 ГБ SSD, 24/7.
4. Помни: на бесплатном тарифе **данные стираются при перезапуске**,
   постоянного диска нет. Для теста и «просто чтобы работало» — нормально.

## Тестовые периоды (если нужен полноценный VPS на месяц)

| Провайдер | Срок | Карта |
| --- | --- | --- |
| Beget | 30 дней | нет |
| SmartApe | 14 дней | нет |
| Timeweb Cloud | 5 дней | нет |
| RUVDS | 3 дня | нет |
| Amvera | приветственный баланс 111 ₽ (~2–3 недели) | нет |
| VDS.GURU | 24 часа | нет |

Дальше минимальный VPS в РФ стоит примерно 150–500 ₽/мес (RUVDS START — 149 ₽,
Timeweb Cloud 15 — 530 ₽). Это дешевле, чем каждый месяц искать новый «бесплатный»
хостинг и терять партии.

## Что проверить перед переездом

1. Останови бота на компьютере/телефоне — **два экземпляра с одним токеном
   конфликтуют**, часть сообщений теряется.
2. Убедись, что хостинг не блокирует исходящие TCP-соединения к Telegram
   (на PaaS обычно всё открыто; на «хостинге сайтов» — нет).
3. Не коммить `.env` и `data/` в git.
4. После первого запуска проверь в логах `Бот запущен: @skldlgkjsjskfkkfheja_bot`
   и сыграй тестовую партию, включая инлайн-режим.
